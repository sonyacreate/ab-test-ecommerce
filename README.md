# A/B-тест: анализ нового дизайна ecommerce

## О проекте

Аналитический кейс по результатам A/B-теста интернет-магазина.

**Бизнес-вопрос:** даёт ли новый дизайн посадочной страницы измеримое улучшение конверсии и есть ли основания менять текущий вариант?

В проекте пройден полный аналитический цикл: проверка качества эксперимента, очистка данных, расчёт ключевых метрик, проверка статистической значимости и неопределённости эффекта, оценка чувствительности теста и бизнес-интерпретация.

## Бизнес-контекст

Компания разделила пользователей на две группы:

- **Control** — старый дизайн;
- **Treatment** — новый дизайн.

Основная метрика — **Conversion Rate (CR)**.

Гипотезы:
- **H0:** конверсия в группах не отличается;
- **H1:** конверсия отличается.

Уровень значимости: **α = 0.05**.

## Данные

Источник: [Kaggle — E-Commerce A/B Testing dataset](https://www.kaggle.com/datasets/putdejudomthai/ecommerce-ab-testing-2022-dataset1)

Исходный датасет:
- **294 480** строк;
- `user_id`;
- `timestamp`;
- `group`;
- `landing_page`;
- `converted`.

После проверки качества и очистки: **290 585 пользователей**.

## Что было сделано

### 1. Проверка качества данных

Проверены пропуски, распределение пользователей по группам, соответствие `group` и `landing_page` и дубликаты пользователей.

Обнаружено:
- **3 893 строки (1.32%)** с несоответствием группы и страницы;
- **2 повторные записи по `user_id`**.

Некорректные наблюдения исключены из основного анализа, чтобы они не искажали сравнение групп.

### 2. Conversion Rate

Рассчитана конверсия отдельно для Control и Treatment и визуализирована разница.

### 3. Статистический тест

Использован **двусторонний z-test для двух пропорций**. Результат интерпретируется вместе с размером эффекта и доверительным интервалом, а не только по p-value.

### 4. Доверительный интервал

Для разницы конверсий `Treatment - Control` рассчитан **95% CI** методом Newcombe.

### 5. MDE и статистическая мощность

Рассчитан **MDE (Minimum Detectable Effect)** при α = 0.05, power = 80% и baseline, равном конверсии Control.

### 6. Проверка качества эксперимента

Дополнительно проверены SRM (Sample Ratio Mismatch), длительность эксперимента, дневная динамика конверсии и стабильность направления эффекта в первой и второй половине эксперимента.

Временные проверки используются как диагностика и не заменяют основной статистический тест.

### 7. Effect Size

Рассчитан **Cohen's h**, чтобы оценить величину различия независимо от одного только p-value.

## Результаты

| Метрика | Control | Treatment |
|---|---:|---:|
| Пользователи | 145 274 | 145 311 |
| Conversion Rate | **12.04%** | **11.88%** |

**Наблюдаемый эффект Treatment − Control: −0.16 п.п.**

Относительное изменение относительно Control: **−1.31%**.

- **p-value ≈ 0.19** — статистически значимого различия при α = 0.05 не обнаружено;
- **95% CI** для разницы включает 0;
- **Cohen's h ≈ 0.0049** — величина наблюдаемого различия очень мала;
- **MDE ≈ 0.34 п.п.** — ориентир минимального эффекта, который тест способен обнаружить при заданных параметрах мощности.

> Важно: отсутствие статистической значимости не означает, что новый дизайн доказанно хуже. Корректный вывод — текущий эксперимент не подтвердил улучшение конверсии.

## Бизнес-интерпретация

На основании основной метрики текущий эксперимент **не подтверждает улучшение конверсии после перехода на новый дизайн**.

Поэтому решение о полном rollout нового варианта не следует принимать как подтверждённое улучшение на основании этого теста.

Следующие шаги:
1. проверить продуктовую гипотезу и возможные причины отсутствия улучшения;
2. определить минимально значимый для бизнеса эффект;
3. при необходимости спланировать новый эксперимент с достаточной мощностью;
4. заранее определить дополнительные guardrail-метрики, например ошибки, возвраты, выручку на пользователя или другие доступные бизнес-метрики.

## Что показывает проект

Этот кейс демонстрирует не только умение посчитать конверсию, но и аналитический подход:

**качество данных → корректность эксперимента → метрики → статистическая значимость → доверительный интервал → практическая значимость → MDE → бизнес-интерпретация.**

Финальный summary в ноутбуке автоматизирован: при изменении данных ключевые метрики и итоговая интерпретация пересчитываются автоматически.
